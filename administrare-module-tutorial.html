Cum funcționează un modul

Un modul este o definiție universală pentru botul Panel Pro Discovery. Administratorul global creează o singură definiție, iar ownerul fiecărui server alege ulterior canalul embedului și canalul de log.

1. Definești modulul
2. Salvezi global
3. Ownerul alege canalele
4. Botul publică și gestionează

Constructorul nu este legat de un Discord anume. Serverul și canalele se aleg numai în pagina de configurare a serverului.

1. Identitatea modulului

Cheie internă

Identificator unic, folosit în Supabase, rute și custom ID-uri Discord. Folosește litere mici, cifre și underscore. Exemplu: custom_recrutare

Nume modul

Numele vizibil în dashboard și în pagina de configurare.

Titlu embed

Titlul mesajului publicat în Discord. Poți folosi emoji.

Descriere embed

Explică utilizatorului ce face modulul și ce se întâmplă după apăsarea butonului.

Culoare

Culoarea barei embedului. Este globală pentru toate serverele.

2. Handler-ele

Doar embed

Modul informativ. Afișează embedul și butoanele, fără formular.

Anunț

Primește o informație și o poate marca drept publicată. Potrivit pentru anunțuri și comunicări.

Cerere

Deschide un formular, salvează solicitarea în Supabase și o trimite în canalul de log.

Aprobare

Salvează cererea ca pending și afișează acțiuni Aprobă/Respinge pentru manageri.

Raport

Numără și afișează înregistrările modulului, respectând limita configurată.

3. Embed avansat

Toate câmpurile sunt opționale:

  • autor și icon autor;
  • thumbnail și imagine mare;
  • footer și icon footer;
  • timestamp automat;
  • până la 25 de câmpuri embed;
  • câmpuri inline pentru prezentare compactă.

URL-urile trebuie să fie publice și să înceapă cu https://, altfel Discord poate refuza imaginea.

4. Formularul modulului

Formularul se afișează în Discord după apăsarea unei acțiuni. Poți adăuga maximum 5 câmpuri, fiecare cu etichetă, tip și caracter obligatoriu.

Tipuri de câmp

  • Text scurt — nume, titlu, identificator;
  • Text lung — descriere, motiv, detalii;
  • Număr — cantitate, sumă, punctaj;
  • Dată — data evenimentului sau termenul;
  • Link — URL valid;
  • Selectare — valori predefinite validate de bot.

Discord acceptă doar Text Input în modal. Pentru Selectare, botul afișează opțiunile în instrucțiuni și validează valoarea introdusă.

5. Butoane și acțiuni

Fiecare buton are propria configurație și nu trebuie să execute aceeași funcție ca celelalte.

Tipuri vizuale

ButonLinkModalMeniu select

Acțiuni

  • Deschide formular — pornește fluxul modulului;
  • Salvează cererea — persistă datele;
  • Trimite log — publică rezultatul în canalul de log;
  • Notifică utilizatorul — răspuns privat;
  • Actualizează mesajul — editează embedul existent;
  • Aprobă/Respinge — procesează o solicitare pending;
  • Generează raport — returnează statistici;
  • Doar confirmare — afișează un mesaj fără procesare.

6. Workflow și acțiuni în lanț

Poți selecta acțiuni care se execută după interacțiune. Pentru o cerere normală, fluxul recomandat este:

Salvează datele → Trimite log → Notifică utilizatorul

Pentru aprobare:

Salvează datele → Trimite log → Butoane aprobare

Pentru raport:

Generează raport → Actualizează embedul

7. Permisiuni și limite

Acces

  • Toți utilizatorii;
  • Roluri configurate — introduci ID-urile rolurilor;
  • Manageri server — Manage Server;
  • Owner server.

Limite

  • Cooldown între trimiteri;
  • număr maxim de cereri pending;
  • număr maxim per utilizator;
  • lungime maximă a textului;
  • atașamente, când fluxul le suportă.

8. Răspunsuri configurabile

Poți personaliza mesajele afișate după procesare:

  • răspuns de succes;
  • răspuns de eroare;
  • confirmare pentru acțiuni simple;
  • răspuns privat sau public.

Recomandarea este ca erorile și confirmările personale să rămână private, iar rezultatele generale să fie publice doar când este necesar.

9. Publicarea pe server

După salvarea modulului global, ownerul serverului intră în Configurare bot și selectează:

  • canalul embedului;
  • canalul de log;
  • serverul pe care este instalat botul.

Butonul de publicare actualizează mesajul existent dacă ruta are un message ID. Dacă nu există, botul creează un mesaj nou și salvează ID-ul.

10. Supabase și submissions

Cererile, aprobările și anunțurile sunt salvate în tabela discovery_custom_module_submissions.

Sunt păstrate modulul, serverul, autorul, valorile formularului, statusul, acțiunea, mesajul Discord și datele de audit.

Statusuri

11. Comenzi slash și checklist final

Dacă completezi o comandă slash, după salvare aceasta trebuie sincronizată prin funcția sync-discord-commands. Comanda apare global și pe serverele configurate.

  • cheia internă este unică;
  • titlul și descrierea sunt completate;
  • handler-ul este ales corect;
  • fiecare buton are acțiunea lui;
  • formularul are câmpurile necesare;
  • permisiunile și limitele sunt verificate;
  • ownerul a configurat canalul embed și log;
  • migrația submissions există în Supabase;
  • comanda slash a fost sincronizată;
  • testul se face cu un utilizator normal și cu un manager.

Pentru testare completă verifică separat: acces permis, acces refuzat, formular valid, formular invalid, cooldown, limită pending, log, actualizare embed și aprobare/respingere.
